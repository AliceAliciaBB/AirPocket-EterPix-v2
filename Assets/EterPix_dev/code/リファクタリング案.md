# prefab構成
- ダウンローダ(仮称):機能urlを受け取り、json/imgをdlし、保存しておく
- リクエスター(仮称):Unity上でバンドルしたurlを保管する子要素に(複数の)モニターを保有する
- モニター(仮称):htmlでuiを構成したやつ画像やjsonからテキストを表示するやつ

# 決定事項 (2026-09-23 /grill-me で合意)

## 全体方針
- **旧系統は削除する**(`eterpix_get_api` / `eterpix_json_api` / `eterpix_update` / `TextureManager` / `eterpix_json_get` / `eterpix_item` / `eterpix_photo_get` / `eterpix_photo_vew`)。
  旧系統にしかない機能(写真クリップの持ち運び、TP予約URL、URLの3本切り替え)も廃止する。
- 今の新系統(`eterpix_json_loader` / `eterpix_image_loader` / `eterpix_middle_*` / `eterpix_cell` / `eterpix_listener_*`)も改造せず、作り直す。
- 新しいコードは `code/v2/` に作る。クラス名は `eterpix_downloader` / `eterpix_requester` / `eterpix_monitor`(既存のクラス名と衝突させない)。
  完成するまで旧コードと並存させ、完成後に旧コードをまとめて削除する。

## サーバー側の前提(`D:\git\eterpix-v10` で確認済み)
- JSON: `GET /api/vrc/public` / `/api/vrc/public_random` / `/api/vrc/{api_key}`(フォルダ)。どれも `new` / `old` / `collage_img` / `world_data` / `posts` を返す。
- 画像: 上記URL + `/{hex}`(`00`〜`ff`)。**スロットは256個のリングバッファー**(現行Unity側の16個前提は誤り)。
- コラージュ画像は2048x1728、2列3行、セル1つ1024x576(16:9)。縦画像はセル内で反時計回り90度回転して配置され、`img_rotation` で戻す。
- サーバーの更新は10分刻みの枠(0,10,20…分)でのみ行われる。確定済みのスロットは不変で、変わるのは最新スロットと、256を超えて上書きされる最古スロットだけ。
- `posts` の各要素で使うキー: `collage_id`, `img_pos`, `img_rotation`, `uuid`, `description`, `user_name`, `world_vrc_id`, `is_r18`, `created_at`。`likes` は含まれない。
- `posts` の並び順は、`/public` が新しい順、`/public_random` がサーバー側でシャッフル(15分ごとに全員共通)。
  `/{api_key}`(フォルダ)は現状古い順になっているバグがあり、サーバー側で直す(https://github.com/AliceAliciaBB/eterpix-v10/issues/8)。

## ダウンローダ (`eterpix_downloader`)
- ワールドに1つだけ置くシングルトン。固定名のGameObjectを `GameObject.Find` で探して解決する。
- **複数フィードに対応する**。リクエスターから受け取ったJSON URLの文字列(`VRCUrl.Get()`)をキーにフィードを登録する。
  同じURLのリクエスターは同じフィードを共有し、違うURLなら新しいフィードとして扱う。
- フィードごとに `posts`(生データ、フィルタ前)、`world_data`、`collage_img` のタイムスタンプを保持する。
- **定期更新**: ダウンローダが1つのスケジュールを持ち、時刻になったら全フィードを順番に取得する(文字列ダウンロードもレート制限があるため直列)。
  スケジュールはサーバーの10分枠に合わせる(現行の「毎時1,11,21…分」方式を踏襲)。オーナーが「今取得しろ」のネットワークイベントだけを送り、データ本体は同期しない。
- **手動更新**: リクエスターのボタンから呼ばれたときは、そのリクエスターのフィードだけを取り直す。
- **画像**: 必要なときだけ取得する(オンデマンド)。ダウンロードは全体で直列1本、優先度キューで順番を決める。キーは(フィード, スロット)。
  - JSONを更新したとき、`collage_img` のタイムスタンプが変わったスロットだけを古いとみなす。表示中なら取り直し、表示していなければ破棄する。
  - 同時に保持するテクスチャは最大M枚(Inspectorで設定、既定8枚≒150MB)。上限を超えたら参照が0のものから破棄する。
  - 参照カウントで管理し、参照が0になったら猶予時間の後に破棄する(現行 `eterpix_image_loader` のBUGSにある破棄漏れ・待機リスト残りは作り直しで解消する)。

## リクエスター (`eterpix_requester`)
- JSON URLを1本(`VRCUrl`)と、画像URLの表(`vrcurllist`、**256件**)を持つ。
  `vrcurllist` は今と同じくエディタでPlay開始前に自動同期する(`arraySize` を256にする)。
- 子要素に複数のモニターを持つ。モニターの参照は、親(リクエスター)が `GetComponentsInChildren(true)` で集めて渡す。
- **扱う範囲**: 新しい順に最大Nスロット分の投稿だけを扱う(Inspectorで設定)。
- **R18**: Inspectorで設定する(既定は隠す)。ゲーム内からは変更できない。フィルタはリクエスターが自分用の番号リストを作るときにかける(ダウンローダは生データを保持するだけ)。
- **並び順**: サーバーの順のままにする。並び替えの設定(`eterpix_selection_order`)は廃止する。ランダムに見せたい場合はURLを `/public_random` にする。

## モニター (`eterpix_monitor`)
- **UIはhtmlモックに合わせる**(`D:\git\eterpix-v10\vrc_ui` の `vrcetepixui.html` / `vrcetepixui.css`。DESIGN.mdと食い違う場合はcssを優先)。
  構成: ヘッダー(ロゴ、ⓘボタン)→ 画像 → ページ送り(`<` `現在/全体` `>`、両端では無効)→ ワールド情報(ワールド名、説明、「ポータルを開く」。ワールド情報が無ければ非表示)→ 投稿情報(投稿者名、説明)→ 情報ウィンドウ(ⓘで開閉)。
- **画像表示**: コラージュから16:9で切り出したあと、`img_rotation` 分を逆回転して正立させ、**4:3の枠に切らずに全体を収める**(縦画像は左右に余白が出る)。
  縦横によるセルの振り分け(`AcceptsOrientation`)は廃止する。
- **ページ位置**: モニターごとに `offset`(開始位置)と、ページ位置を持つ。
  - ページ位置は `[UdonSynced]` で全員に同期する。送った人がそのモニターのオーナーになり、`RequestSerialization` する。
  - 同期するのは番号(何番目か)。新着でJSONが更新されたときに表示がずれるのは許容する。
- **画像の読み込み**: モニターごとにトリガーColliderを持ち、ローカルプレイヤーが範囲に入ったら画像を要求し、出たら解放する。
  - Colliderはレイキャストを遮らないレイヤー(例: `Ignore Raycast`)に置く。そのレイヤーがPlayerLocalと衝突判定する設定であることを確認する。
  - 範囲外のモニターは、ページ位置の同期は続け、画像はプレースホルダー表示にする。
- **ポータル**: モニターごとに1つずつ `VRCPortalMarker` を持つ。「ポータルを開く」を押した本人にだけ見える(ローカル)。3m離れたら自動で消える。
