## 仕様(2026-10-31 合意 + 2026-11-02 実装に合わせて改訂)

- モックの収録画面: 起動(ロード中 / 完了 / 取得失敗)、スワイプ(横・黒 / 縦・白)、拡大、すべて見た後、「もう一度見る」確認、ワールド詳細、通知、気になる投稿一覧、設定、情報、グループ

### データ(vrc-api v1)

- 実際のアプリは、本番の vrc-api v1 の `GET /api/vrc/v1/public`(と、画像の `/api/vrc/v1/public/<hex>`)を用いる
- モックの投稿・写真・名前・ワールド名は、すべて架空のサンプルで、実在のものは含まない。JSONのキー名(`coid` / `copo` / `coro` / `usna` / `ussf` / `pode` / `woid` / `wopf` / `poca` など)と、コラージュ画像のUV切り出し・回転(`coro`)は、v1と同じ作りにしている
- フィールドの定義は `docs/contracts/vrc-api-v1-schema.md` を参照する
- 画面との対応

    | キー | 画面での使い方 |
    |---|---|
    | `poid` | 投稿1件 = カード1枚 |
    | `usna` + `ussf` | 投稿者名と、後ろの[称号] |
    | `wona` + `wopf` | ワールド名と、手入力の印(例:【追記】)。ワールド名の前に付ける |
    | `woid` | NudeNyangの既存ポータルに渡すワールドID。空ならポータルを出せず、下スワイプではカード下に「ワールド情報なし」と一瞬出す |
    | `coid` / `copo` | 写真がどのコラージュの何番目か(画面には出さない) |
    | `poca` | 画面には出さない(一覧の日時表示は説明文に置き換えた) |
    | `pode` | 説明文。スワイプ・拡大の情報帯と一覧の行に、最大2行で出す。改行は空白に直す |
    | `wode` / `woau` | ワールド詳細の説明・作者(`woda` のキー) |

- コラージュは別々の投稿の写真を最大6枚(2列×3行)貼り合わせた、取得のための梱包。`copo`(1〜6)が左上から右へ、下の行へと並ぶ番号
- 通信まわり(サーバー停止など)の文言は「共通 > 状態の表示」を参照

### 1. 起動画面

- ロゴ「EterPix」(88・アクセント色)、紹介文(26)、進行バー「ロード中...〇%」を出し、完了後に「push to start」を押して先へ進む
- 「ロード完了」は、投稿データの取得と、先頭のコラージュ数枚(`startupPreload`。仮に3枚)の画像が揃ったとき。残りは開始後に裏で取得する(画像は5秒間隔で直列に取るため、全部を待つと約130秒かかる)
- 配置(本体 = ヘッダーとフッターの間): ロゴは上から 60〜200、紹介文は高さの 28〜66%、ロード行は横 20〜80%・下から 8〜30%、push to start は横 35〜65%・下から 10〜26%
- フッター(高さ56): 「2026 EterPix All Rights Reserved.」(20px・薄い文字)

### 2. スワイプ画面

- カード1枚 = 投稿1件。コラージュは、VRCUrlの制限に対応するための取得用の梱包(最大6枚、2列×3行)で、カードの単位ではない。各投稿が `coid` / `copo`(1〜6) / `coro` を持つ
- カード(面 #1F1F1F): 横はパネル幅の 17%〜83%(横向きで 774.4)、上から 12・**下から 12**(ボタン列を無くしたため。横向きで高さ 504)。**方向ラベルの置き場**(2026-11-02): 上下は縦横とも、カードの上端・下端の24pxの帯(上=「[下スワイプのアイコン]:前の投稿」、下=「[上スワイプのアイコン]:次の投稿」。アイコン24px・文字16px)。**左右は、横向きではカードの外の空き領域**(パネルの左端〜カード=幅17%ずつ・本体の高さいっぱい)を使い、「[左スワイプ]ワールド情報」(左)と「[右スワイプ]気になる」(右)を、**縦書き**(縦向きと同じ。アイコンが上・文字が下)・アイコン72px・文字44pxで、領域の中央に大きく置く。縦向きは空き領域が無いので、カード内の左右24pxの帯に縦書きで置く(アイコン24px・文字16px)。写真は、横向きは**上下24pxを空けてカードの左右いっぱい**(774.4×456の枠に16:9で収める=774.4×435.6)、縦向きは上下左右とも 24px の空きを空けて収める。(旧記述: この空きに**方向ラベル**を置く。アイコンは実PNG `swipe_up/down/left/right`(100dp・E3E3E3)を文字色で着色して24pxで表示。上の帯=「[下スワイプのアイコン]:前の投稿」、下の帯=「[上スワイプのアイコン]:次の投稿」、左の帯=「[左スワイプのアイコン]:ワールド情報」、右の帯=「[右スワイプのアイコン]:気になる」。文字は16px・文字色(黒=白/白=#141414)。左右の帯は幅24pxなので文字は縦書き。入れ替え設定を「する」にすると上下の文字だけ入れ替わる(アイコンは動かさない))。写真は縦横比を保って収める。縦写真(`coro` が奇数)は**スワイプ画面では縦のまま(正立)**収める(2026-11-01 の指示。Padの「倒す」から変更)
- 情報帯(黒の50%半透明・文字は白)。**横向き**は写真の下端に重ねる。**縦向き**は写真に重ねず、カードの下部(下24px・左右24px)に独立して置き、写真はその上の領域(下から「24+帯の高さ」を除いた範囲)に収める(縦向きは写真の領域に余裕が無く、重ねる必要が無いため)。以下は帯の中身。1行目に投稿者名[称号](26)、2行目に説明文(20・最大2行。無ければ欄ごと詰めて帯を低くする)、3行目にワールド名(20・薄い)。帯の高さは説明なしで 76
- **操作(追加計画V。追加計画Uの方向割り当てを変更)**: 写真を4方向にドラッグして**離したときに**確定する

    | 方向 | 動作 |
    |---|---|
    | 上スワイプ | 次の投稿へ進む(入れ替え時は前の投稿へ戻る) |
    | 下スワイプ | 前の投稿へ戻る(入れ替え時は次の投稿へ進む) |
    | 右 | 気になる ☆⇔★ のトグル(進まない) |
    | 左 | ワールド詳細を開く |

    - **判定リング**: 指を置いた点(開始点)を中心にした円。半径は**カードの短辺の12%**(横向きで 504 × 0.12 ≒ 60px)。**離したときに現在点がリングの外にあれば、スワイプ入力とみなす**。リングの内側で離したときは入力としない(従来の「カード幅・高さの12%」と「横が縦の1.3倍」の軸ロックは廃止)
    - 方向は、開始点から現在点へのずれ(dx, dy)の**絶対値が大きい軸**で決める(斜めも上下左右の4方向に丸める)。感度の倍率(本体の `swipeSensitivity`)は掛けない
    - **画面外**: ドラッグ中に指(レーザー)がタブレットのパネルの外へ出たら、そのドラッグは**無視**し、入力とみなさない(離しても確定しない)。パネルの内側ならカードの外でも有効
    - ワールド情報が無い投稿は、左スワイプで開かず、「ワールド情報なし」を一瞬出す(位置はカードの下端付近。仮)
    - 先頭で下スワイプ(前の投稿)は何もしない。最後のカードで上スワイプ(次の投稿)は終了画面へ。終了画面では 下スワイプ=最後のカードへ戻る、上・右・左は無効
    - 矢印キー(スワイプと同じ向き): ↑=次の投稿、↓=前の投稿、→=☆/★、←=ワールド詳細(入れ替え設定は上下の意味を入れ替える)
- **デバッグ用表示**(ドラッグ中だけ、パネルの全面に重ねて出す。実機での調整用。仮の見た目):
    - 開始点: 指を置いた位置の点(直径16・白)
    - 現在点: 今の指の位置の点(直径16・アクセント色)
    - 帯: 開始点と現在点を結ぶ長方形の帯(太さ6・白の50%半透明)
    - 判定リング: 開始点を中心にした円の枠(半径は上記。太さ4。現在点がリングの外なら アクセント色、内なら白 = 離すと入力になるかが見てわかる)
    - ログも出す: `[EtpTrace] eterpix-app swipe ... start=(x,y) cur=(x,y) r=... outside=... dir=... panelOut=...`
- **ボタン列は一旦なし**: 追加計画Uの [戻る][更新][ポータル][☆/★][進む] は表示しない(機能の中身は残すが、画面から押せない)。到達手段が無くなるもの: **更新(リロード)**(スワイプにも割り当てない)。ポータルはワールド詳細の「ポータルを開く」から開ける
- 拡大: **ダブルタップのみ**(0.35秒以内の同じ写真への2回。単押しでは開かない)。開く → 拡大(情報帯あり) → 押す → 情報帯も消えて写真だけ → 押す → 元の画面に戻る
    - 拡大はパネル全面(ヘッダー・フッターも覆う。背景は黒でテーマに従わない)。情報帯(高さ84)は投稿者名(28)とワールド名(22)。説明文は説明があれば出す(実装)
    - 縦横どちらの写真にも、Pad(K-4: `docs/plans/etrpix-pad-plan.md`)と同じ「長辺をモニターの長辺に、短辺を短辺に合わせ、食い違うときは反時計回りに90°回す」を適用する
- ワールド詳細(下スワイプで開く): 全面の暗幕(黒の60%)と、中央のカード(横 15〜85%・縦 8〜92%)。中身は上から ワールド名(32・2行まで)/ 作者(22。あるときだけ「作者: 〜」)/ 説明(24・長ければスクロール)/ 下端に「ポータルを開く」(アクセント・左58%)と「閉じる」。「閉じる」・暗幕・上スワイプで閉じる。ポータルを置く最中は閉じて操作できる。開いている間は他の操作は無効。開閉は画面同期の対象
- 画面同期: 操作した人の画面(基準の画面・今のカード・拡大・白黒・☆/★・ワールド詳細の開閉)を、他のプレイヤーにも映す(NudeNyang 本体のフィードと同じ Manual 同期。投稿は添字でなく `poid` で指す)。更新中・進む戻る入れ替えは同期しない。複数クライアントでの実機確認は未了
- すべて見た後: 「すべての投稿を見ました」「気になる: N 件」(34)と「もう一度見る」ボタンのみ。「気になる投稿一覧を見る」ボタンは無い(ヘッダーの一覧ボタンから開く)。「もう一度見る」を押すとモーダル(暗幕の中央)で「気になる選択はなくなります。いいですか?」を出し、「はい」(アクセント)で気になる選択を消して最初から選び直し、「やめる」で元に戻る

### 3. 気になる投稿一覧

- ヘッダー右端の気になる一覧ボタン(星のアイコン)で開く(「気になる」の印は ☆/★ 。10-31 の「右スワイプで気になる」は廃止)。固定の見出し「気になる投稿 N 件」(29。上から 10〜53)。0件なら「気になる投稿はありません」(30)
- 行は上から 72 の位置から、1行 192 の高さで 211 おきに並ぶ(行の背景は無し)。左に画像 192×192(中央を1:1に切り取る。横写真は左右が、縦写真は上下が切れる)。右の列(画像の右 211 から)は、上から 名前[称号](19・1行)/ ワールド名(16・薄い・1行。ワールドが無い行は出さない)/ 説明文(16・薄い・2行まで。**日時は出さない**)。ワールドが無い行は説明を上へ詰める
- ボタンは行の右下に1行で右寄せ(高さ43・間隔10・文字19)。左から「WEB(幅81)| 高画質(幅96)| ポータルを開く(幅173・アクセント)」。縦向きでも折り返さない
- WEB・高画質は押すと VRChat の入力欄が開き、そこで URL をコピーする(NudeNyang の他のコピー欄と同じ方式)。WEB = `https://eterpix.com/web/post/<poid>`、高画質 = Pad用 `https://eterpix.com/api/vrc/v1/pad/<poid>`
- 画像を押す(ダブルタップ)と、スワイプ画面と同じ流れで拡大し(情報帯あり → 写真だけ)、最後は一覧に戻る
- ポータル: 押す → 床を指して置く → 開く。置いている最中にもう一度押すと取り消し。ワールドIDが無い投稿(`woid` が空)はポータルのボタンを出さない
- 一覧・情報ページは、ボタンの無い所でもレーザーでスクロールできる

### ポータル

- NudeNyang側の既存機能(`NudeNyangTravelPortal`)をそのまま使い、EterPix-appでは作らない
- 床を指してクリックで配置する。同時に1つ、再配置まで30秒、15秒で消える
- `BeginPlacement(worldId, NudeNyangTravel app)` はTravelアプリ(アプリ番号11)の表示中しか呼べないため、EterPix-app用にNudeNyang側へ少しの修正が必要になる。EterPix-appはNudeNyangの12番目のアプリとして追加する(`AppCount` 11 → 12)

### 未決

- WEB(eterpix.com の投稿ページを開く想定。URL形式は未確認)と、高画質(フル画質 `/api/images/<post_uuid>` を出す想定)の動作
- ポータルの方式: A(`BeginPlacement`: 床を指して配置)を採用して実装済み(本体へのパッチP10)。実機での配置は未確認
- 気になる(☆/★)をサーバーに保存するか(現状はセッション内だけで、保存しない)。保存する場合は、Web側のAPI・DBの追加が要り、`docs/impact-matrix.md` の確認が必要
- 「ロード終了後[2]画面へ移る」と「push to start」の関係(モックはボタンで移る)
- 縦写真を大きく見せる方法、拡大(UIなし)から戻る時にスワイプの結果を付けるか、回転の向き(モックは時計回り。K-4に指定なし)、一覧の画像の切り取り位置(中央固定)
- 写真に文字を重ねる例外を、このカードだけにするか
- VRChat内でのドラッグ操作の感触(未確認)。下の帯のボタンを併設しているのは、そのため
- 仮のもの: グループ説明の文面、ロゴ。実機でしか確認できないもの: 4方向スワイプの手触りとしきい値、レーザーでのスクロール、ポータルの実配置、複数クライアントの同期、画像キャッシュ上限(`maxCached` 仮24)
- 件数(実機の上限)は「投稿の件数」の節を参照。モックの20件・4コラージュは、HTMLモックから外した(実データはv1から取得する)
