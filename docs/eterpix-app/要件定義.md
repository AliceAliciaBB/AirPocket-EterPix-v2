# VRC-NudeNyangTablet_app

- 対抗馬に対して積極的に乗っかることで普及させようという魂胆

## 画面構成

- 共通画面
    - i (インフォメーション)
    - グループ (グループ説明)
    - テーマ切り替え(白/黒)
- ロード後利用できる画面
    - 気になる投稿一覧

1. 起動画面(ロード)

    初回起動時に表示される。共通画面への遷移可能　ロード終了後[2]画面へ移る

2. スワイプ画面

    投稿をスワイプして気にならない/気になるで確認できる

3. 気になる投稿一覧

    リスト状で確認できる

## 投稿の件数

- スワイプ画面で扱う投稿の件数は、できるだけ多くする
- 上限は、タブレットが保持できる画像のキャッシュ数で決まると考えられる。実機で確認するまで、どこまで増やせるかは分からない(未確認)
- HTMLモックは、取得時点の実データ20件で作っている。この20件は仮の数字で、実機の上限を示すものではない

## モックで合意した内容(2026-10-31)

HTMLモック([`docs/mocks/eterpix-app-mock.html`](mocks/eterpix-app-mock.html)。ブラウザで開く1ファイル)で確認し、合意した内容。下の「UI案」のHTMLは初期案で、食い違う部分はこの節が優先する。

### データ(vrc-api v1)

- 実際のアプリは、本番の vrc-api v1 の `GET /api/vrc/v1/public`(と、画像の `/api/vrc/v1/public/<hex>`)を用いる
- モックの投稿・写真・名前・ワールド名は、すべて架空のサンプルで、実在のものは含まない。JSONのキー名(`coid` / `copo` / `coro` / `usna` / `ussf` / `pode` / `woid` / `wopf` / `poca` など)と、コラージュ画像のUV切り出し・回転(`coro`)は、v1と同じ作りにしている
- フィールドの定義は `docs/contracts/vrc-api-v1-schema.md` を参照する

### 共通

- 名称: 「TinderUI」は他社サービスの名前なので使わず、「スワイプ画面」と呼ぶ
- UIはUnity側の規則(Unityリポジトリの `docs/eterpix-monitor-ui-remake-spec.md`)に従う
    - 全要素が長方形(角丸・ピル形なし)。線なし。区切りは余白(単位8、外側16)
    - 面の色を持つのはボタンだけ。色は不透明。文字は1色(薄い文字なし)
    - フォントは NotoSansJP-Bold の1種で、強弱はサイズで付ける
    - 黒テーマ #141414 / 白テーマ #FAFAFA。ボタンは #2A2A2A / #E6E6E6、押下 #3A3A3A / #D4D4D4、アクセント #9D6FFF(その上の文字は #141414)
- 例外: 写真の上に、文字(情報帯)を50%半透明で重ねてよい(Unity側の「写真に重ねない」への例外。このカードだけの例外か、今後も外すかは未決)
- ヘッダー: 高さ40、ボタン40×40、上に16pxの余白
    - 左: ロゴ「EterPix-app」
    - 中央: スワイプ画面だけ「現在 / 総数」
    - 右(左から): ♡(ロード後) → テーマ切り替え → グループ → i
    - ♡・グループ・i は、開いている間は ✕ に変わり、同じボタンで元の画面に戻る
- 情報画面(i)の末尾に「最新情報は X @_alicilia」を載せる
- 状態の表示: 通常 / 読み込み中 / URL未許可 / サーバー停止 / 投稿0件。読み込み中は写真枠が明滅する。読み込み中・0件は写真枠の中に出し、ヘッダーは常に表示する
- ロゴ(2×3の格子)とグループ説明の文面は仮

### 1. 起動画面

- ロードは約4秒(モックの値)。ロゴ、紹介文、進行バー「ロード中...〇%」を出し、完了後に「push to start」を押して先へ進む
- フッター: 「2026 EterPix All Rights Reserved.」

### 2. スワイプ画面

- カード1枚 = 投稿1件。コラージュは、VRCUrlの制限に対応するための取得用の梱包(最大6枚、2列×3行)で、カードの単位ではない。各投稿が `coid` / `copo`(1〜6) / `coro` を持つ
- 写真は枠いっぱいに、縦横比を保って出す。縦写真は `coro` が奇数のものとして判定する
- 写真の下端に、情報帯(投稿者名[称号]、ワールド名など)を50%半透明で重ねる
- 操作: ドラッグ(左 = 気にならない / 右 = 気になる)、矢印キー、写真の下の帯のボタン(左 = 気にならない / 右 = 気になる。ドラッグ中は色づく)。次のカードは真下に隠れている
- 拡大: 写真を押す → 拡大(UIあり) → 押す → UIなし(写真だけ) → 押す → 元の画面に戻る
    - 「UIあり」は、投稿者名・ワールド名の情報帯だけ。ヘッダー・フッターは出さない
    - 縦横どちらの写真にも、Pad(K-4: `docs/plans/etrpix-pad-plan.md`)と同じ「長辺をモニターの長辺に、短辺を短辺に合わせ、食い違うときは90°回す」を適用する
- すべて見た後: 「気になる投稿一覧を見る」と「もう一度見る」を出す。「もう一度見る」を押すとモーダルで「気になる選択はなくなります。いいですか?」を出し、「はい」で気になる選択を消して最初から選び直し、「やめる」で元に戻る

### 3. 気になる投稿一覧

- ♡で開く。1件は2段の構成で、1段目「画像 | 説明」、2段目「画像(続き) | ボタン」
- 画像は中央を1:1に切り取る(横写真は左右が、縦写真は上下が切れる)。画像を押すと、スワイプ画面と同じ流れで拡大し(UIあり → UIなし)、最後は一覧に戻る
- ボタンは右寄せ(`justify-content: flex-end`)で、左から「WEB | 高画質 | ポータルを開く」
- 押しても文字を変えないボタン: WEB、高画質(最初に確保した領域を超えないため)。高画質は押すと面の色だけが変わる
- ポータルのボタンの文字: 「ポータルを開く」 → 押すと「ポータルを置く」 → 「ポータル開いた」 → 元に戻る
- ワールドIDが無い投稿(`woid` が空)は、ポータルのボタンを出さず「ワールド情報なし」と表示する

### ポータル

- NudeNyang側の既存機能(`NudeNyangTravelPortal`)をそのまま使い、EterPix-appでは作らない
- 床を指してクリックで配置する。同時に1つ、再配置まで30秒、15秒で消える
- `BeginPlacement(worldId, NudeNyangTravel app)` はTravelアプリ(アプリ番号11)の表示中しか呼べないため、EterPix-app用にNudeNyang側へ少しの修正が必要になる。EterPix-appはNudeNyangの12番目のアプリとして追加する(`AppCount` 11 → 12)

### 未決

- WEB(eterpix.com の投稿ページを開く想定。URL形式は未確認)と、高画質(フル画質 `/api/images/<post_uuid>` を出す想定)の動作
- ポータルの方式: A(`BeginPlacement`: 床を指して配置。推奨) か B(`Open`: 固定のマーカーに開く)
- 右スワイプ(気になる)をサーバーに保存するか(する場合は、Web側のAPI・DBの追加が要り、`docs/impact-matrix.md` の確認が必要)
- 「ロード終了後[2]画面へ移る」と「push to start」の関係(モックはボタンで移る)
- 縦写真を大きく見せる方法、拡大(UIなし)から戻る時にスワイプの結果を付けるか、回転の向き(モックは時計回り。K-4に指定なし)、一覧の画像の切り取り位置(中央固定)
- 写真に文字を重ねる例外を、このカードだけにするか
