### prefab の作り方: ビルダーで生成する(2026-11-14 ユーザー決定)

モックはまだよく変わるので、v2 の prefab は**ビルダーのコードが正**で、prefab は生成物とする. v1 のモニター(prefab 本体が正・builder 凍結)とは運用を分ける.

```text
Assets/EterPix_dev/UIv2/Editor/   (配布しない)
  Etp2Spec.cs      モックの数字・色・文言をまとめた定数. モック md の章番号をコメントに書く
  Etp2Builder.cs   メニュー「EterPix/UIv2/prefab をビルド」. 4画面 + Etp2_Theme を作り直す
  Etp2BuilderParts.cs  部品を作る関数(3.3)
```

- モックが変わったら、まず `Etp2Spec.cs`(数字・色・文言)を直し、形が変わるときは組み立てコードを直して、ビルドし直す
- **prefab を手で直さない**(次のビルドで消える). 見た目の調整は `Etp2Spec.cs` の値で行う
- **作り直しても消えないもの**: ビルダーは既存の prefab を `LoadPrefabContents` で開き、**ルートのオブジェクトとルートの部品は残して子だけ作り直す**. ルートの fileID が変わらないので、シーンに置いたインスタンスの位置・回転・縮尺と、ルートの部品に書いた値(参照するビューア、ダミーデータなど)は残る. ワールド作者が触る設定は必ずルートの部品に置く
- U# の部品は `AddUdonSharpComponent<T>()`、値を入れたら `UdonSharpEditorUtility.CopyProxyToUdon`、ボタンは `UnityEventTools.AddStringPersistentListener(onClick, 裏の UdonBehaviour.SendCustomEvent, "イベント名")` で配線する(`Assets/EterPixNudeNyang/Editor/EterPixAppBuilder.cs` と同じやり方). U# の `.asset`(UdonSharpProgramAsset)が無ければビルダーが作る
- 色の配列(テーマの塗り先)・行の使い回しの配列もビルダーが作りながら入れる(名前の接頭辞で集め直す必要が無い)
- 同じ入力で2回ビルドしたら prefab の差分が出ないようにする(名前・順番を固定し、乱数や時刻を使わない)
- 生成した prefab もコミットする

## 3. 共通の仕組み

### 3.1 テーマ: `etp2_theme`(ワールドに1つ)と `etp2_theme_target`(画面ごと)

- 色は7役: 背景・文字・ボタン・押下・アクセント・アクセントの文字・押せない文字(モック 1.2 の表の値)
- `etp2_theme`: v1 の `eterpix_theme` と同じ作り(切り替え可/黒固定/白固定、PlayerData で保持). 保存キーは `eterpix.ui2.theme` で v1 とは別
- `etp2_theme_target`: 画面の子を名前の接頭辞で集めて色を塗る. v1 の接頭辞に2つ足す

| 接頭辞 | 塗るもの |
|---|---|
| `bg_` | 背景色の Image |
| `tx_` | 文字色の TMP / Image(アイコン) |
| `btn_` | ボタン(下の「押下色の出し方」) |
| `acc_` | アクセント色の Image |
| `acctx_` | アクセントの文字の TMP |
| `dis_` | 押せない文字の TMP(新) |
| `dim_` | 暗幕(黒 α0.5. テーマで変えない. 集めない) |

- **押下色の出し方**: ボタンの Image の色は白にし、Button の Transition = Color Tint、`ColorBlock` の normal/highlighted/selected = ボタン色、pressed = 押下色、disabled = ボタン色、colorMultiplier = 1、fadeDuration = 0 にする. 選択中(アクセント)にするときは normal/highlighted/selected をアクセント色にする. テーマを変えると `etp2_theme_target` が ColorBlock を書き直す
- 塗り先の配列はビルダーが入れる(v1 の「子から自動収集」ボタンは作らない). 接頭辞はオブジェクト名に付けて、どの役で塗るかを見て分かるようにしておく

### 3.2 ホバーの札: `etp2_tooltip`(画面ごと)と `etp2_hover`(ボタンごと)

- `etp2_hover`: 札に出す文言を持つ. ボタンに `EventTrigger` を付け、PointerEnter / PointerExit / PointerDown から `SendCustomEvent` で自分を呼ぶ
- `etp2_tooltip`: 画面の一番上に札を1枚持つ. 当ててから 0.3 秒(`SendCustomEventDelayedSeconds` + 世代番号で取り消し)で出す. 離す・押すで消す
- 位置: ボタンの下 8(ナビボタンは右 8). はみ出すなら反対側、それでもはみ出す分は内側へ. 札の Image / TMP は `raycastTarget = false`
- 文字幅に合わせた幅は `TMP.GetPreferredValues` で決める
- 鍵の文言(「鍵をかける」/「鍵を外す」)・展開ボタン(「ひろげる」/「たたむ」)は状態で書き換える

### 3.3 部品(ビルダーの関数)

モック 1.4 の部品を、`Etp2BuilderParts.cs` の関数にする. 画面はこの関数を呼んで並べる. 部品の prefab(入れ子の prefab)は作らない(作り直す順番と参照の付け直しが増えるため).

| 関数 | 中身 |
|---|---|
| `Etp2_IconButton` | 40×40 の Button + アイコン Image 20×20 + `etp2_hover` |
| `Etp2_CloseButton` | 40×40 の Button + 20×2 の長方形2本を ±45° |
| `Etp2_TextButton` | 高さ 40、左右余白 16 の Button + TMP 16 |
| `Etp2_AccentButton` | 同上でアクセント色 |
| `Etp2_Segment2` | 2つのボタンを間 8 で等分(HorizontalLayoutGroup) |
| `Etp2_UrlField` | 高さ 36 の読み取り専用 `TMP_InputField`(v1 と同じ) |
| `Etp2_Divider` | 高さ 2 の Image |
| `Etp2_Circle32` | 32×32 の丸 Image |
| `Etp2_ScrollPage` | ScrollRect + 縦スクロールバー幅 8(Visibility は Permanent. 中身がずれないよう幅を最初から取る) + 中身(VerticalLayoutGroup、間 8) |

### 3.4 ボタンに番号を持たせる

U# のボタンは押したとき引数を渡せないので、ナビボタン・ドロップダウンの行・一覧の行などは、行ごとに小さな U# (`etp2_index_button`: 番号と送り先を持つ)を付け、押されたら送り先に「何番が押されたか」を渡す. 行は最大数ぶん先に並べておき、使わない分は非表示にする(使い回し).

### 3.5 ダミーデータ: `etp2_mock_data`

投稿の一覧をインスペクターの配列で持つ(ユーザー名・称号・投稿日時・閲覧数・すーぱーいいね・いいね・写真説明・ワールド名・作者名・ワールドの説明・写真の色). ワールド一覧も同様. フォトフレームごとに「どの投稿を何件出すか」を持つ.
第3段階でこの部品を JSON 読み込みに差し替える. 画面側はこの部品から読むだけにする.

### 3.6 ログ

モックの動きを検証できるよう、主な動き(ページ切替・テーマ変更・フォトフレームを開く・前/次・ソートの適用)を `[Etp2Trace]` 接頭辞で `Debug.Log` に出す.

- 骨組みはメニューモニターと同じ(ナビ 3項目. `etp2_nav` を使い回す)

## 6. 気をつけること

- ナビを広げたときの帯と暗幕、ドロップダウンの一覧、ホバーの札は「ほかの要素の上」に出す. 同じ Canvas の中では兄弟の並び順で決まるので、画面ごとに「上に重ねる層」の空オブジェクトを一番下(描画は一番上)に置き、そこへ移して出す
- VRChat の UI は Canvas に `VRC_UiShape` が要り、レイヤーは Default か UI のまま(v1 と同じ)
- ScrollRect の中のボタンは、スクロールの操作と押すのを取り合う. v1 で問題が無かった設定(drag threshold など)に合わせる
- 押せないボタンの文字の灰色、暗幕だけが「不透明」「長方形」の決まりの例外(モック 1.1). ほかに例外を増やさない

## 9. 追加: ビューアを開いている間のモニターの置き場所(2026-11-14 ユーザー依頼)

| モニター | ふだん | ビューアを開いている間 | ビューアを閉じたら |
|---|---|---|---|
| メニューモニター | ワールド作者が置いた場所(玄関など. 説明として常に出す) | ビューアの左隣へ移る | 元の場所(位置・向き)へ戻る |
| 詳細モニター(ワールドに1つ) | 出さない | ビューアの右隣に出る | 隠れる |

- 開く・閉じるはローカルなので、移動・表示も押した人の画面だけ
- 隣の位置: ビューアのルートから横に (幅 560 + 間 32) ずらす. 上端・向きはビューアにそろえる(モックの並びと同じ)
- 作り:
  - `etp2_viewer` に「メニューモニター」の参照(ワールド作者がつなぐ)を足す. `OpenFrame` で `menu.MoveBeside` / `detail.ShowBeside`、`OnClose` で `menu.ReturnHome` / `detail.Hide` を呼ぶ
  - 詳細モニターはルートの部品を有効のまま、子の Screen だけを出し入れする(非表示のオブジェクトの U# は初期化されず、呼び出しが届かないことがあるため)
  - メニューモニターの元の場所は、最初に動かす前に覚える
- 確かめ方: テストシーンのメニューモニターをビューアから離して置き、開く・閉じるで移動・復帰と、詳細モニターの出し入れを見る

## 10. 追加: フォトフレームの前にビューアを出す・凡例(2026-11-14 ユーザー依頼)

- フォトフレームを開いたら、ビューアをそのフォトフレームの「ビューアの位置」へ移す. メニューモニター・詳細モニターは 9章のとおりビューアの左右に付く(押した人の画面だけ)
- 「ビューアの位置」(`ViewerAnchor`)はフォトフレームの子. 初めの位置はフォトフレームの 0.5m 手前、ビューアの中心がフォトフレームの中心と同じ高さ
- 凡例: `ViewerAnchor` の子に黒い板(中央 = ビューア 560×672、左右 = メニュー・詳細 560×792、間 32. 名前の文字付き)
  - `EditorOnly` タグ(VRChat に上げるときに外れる). エディタの Play 中はフォトフレームの Start で隠す
  - ワールド作者は凡例を動かして位置を決める. `ViewerAnchor` に `[SelectionBase]` の U#(`etp2_viewer_anchor`. 中身なし)を付け、板をクリックすると `ViewerAnchor` が選ばれるようにする
- ビルダー: `ViewerAnchor` は作り直さずに残す(位置・向きと、シーンでの調整を消さないため). 凡例の板だけ作り直す
- 気をつけること: 凡例の大きさは、フォトフレームのルートの縮尺が既定(0.00125)のときに合う. フォトフレームを拡大縮小すると、凡例と実際のビューアの大きさがずれる(位置・向きは合う)
